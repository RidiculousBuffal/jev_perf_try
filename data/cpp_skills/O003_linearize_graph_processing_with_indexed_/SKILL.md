## When to use
- A loop repeatedly rescans all vertices or edges, especially while(true) around DFS or graph scans.
- A loop over every vertex launches DFS, or every outgoing edge can trigger another traversal.
- A functional graph has one successor per node and the query step count is large or 64-bit.
- Cycle detection is present, but the solution still replays up to K transitions or rebuilds full cycle-index arrays.
- A dense adjacency matrix is used even though edges are sparse or generated by a simple rule such as divisibility.
- Recursive DFS may reach 1e5 or more frames, creating stack-overflow risk.
- Graph state is stored in maps, sets, pair-heavy records, or oversized 64-bit arrays in a hot traversal.
- A consistency checker computes extra extrema, counts, or summaries that do not affect the output.

## Steps
1. Write down the exact invariant and output dependency before changing the implementation; remove state that does not affect correctness.
2. Choose the true graph model: functional graph, DAG, SCC condensation, tree/unicyclic graph, difference constraints, flow network, or parity/potential constraints.
3. Use compact 32-bit indices, flags, degrees, and edge links; reserve 64-bit values only for capacities, weights, potentials, or counts that require them.
4. Replace dense matrices and coordinate-based map/set neighbor discovery with compressed vertex IDs and sparse adjacency lists or flat edge pools.
5. Build only actual edges. For structured graphs, generate neighbors directly instead of scanning all possible destinations.
6. Prefer iterative traversal for deep graphs: Kahn's algorithm for topological order, explicit stacks for DFS, and queues for component propagation.
7. For consistency constraints, assign one potential or parity per component and validate every stored edge after propagation; abort on the first contradiction.
8. For functional graphs, store the walk and first-visit index for every reached node. On repetition, split prefix and cycle and answer large K with normalized modulo indexing.

## Pitfalls
- Changing a marker array's meaning without updating every predicate can reverse the pruning direction and produce either wrong answers or repeated work.
- Cycle modulo formulas are vulnerable to prefix-boundary and signed-remainder errors; use nonnegative cycle offsets and explicit zero-based indexing.
- Cycle detection that is followed by step-by-step replay still has O(K) behavior; detection alone is not cycle compression.
- Using parent vertex rather than parent edge in lowlink DFS mishandles parallel edges.
- Starting DFS from only one root silently ignores disconnected components.
- Replacing an exact algorithm with a fast heuristic changes semantics; retain the exact formulation unless approximation is permitted.
- A recursive implementation may be linear but still fail from stack exhaustion on a path-shaped graph.
- Dense matrices can make sparse graph searches pay O(V) per expansion and inflate memory bandwidth.

## When not to use
- Do not replace a correct linear algorithm merely for cosmetic changes when constraints are small and measured runtime is already safe.
- Do not use iterative or sparse representations if the graph is genuinely dense and dense matrix operations are required or cache-optimal.
- Do not use functional-graph cycle reduction when nodes have multiple successors or the transition depends on additional untracked state.
- Do not use tree, unicyclic, or DAG-specific processing without proving the structural precondition.
- Do not replace exact flow, DP, SCC, or reachability logic with a heuristic unless approximation is explicitly accepted.
- Do not use backtracking instead of subset DP when dense graphs make most states reachable and state reuse is high.

## Minimal example
Before:
```cpp
int reachable(const Graph& g, int s) {
  std::unordered_set<int> seen; std::vector<int> q{s};
  for (size_t i=0; i<q.size(); ++i) if (seen.insert(q[i]).second)
    q.insert(q.end(), g.neighbors(q[i]).begin(), g.neighbors(q[i]).end());
  return seen.size();
}
```
After:
```cpp
int reachable(const std::vector<std::vector<int>>& g, int s) {
  static std::vector<int> seen(g.size()); static int stamp = 0; ++stamp;
  std::vector<int> q{ s }; seen[s] = stamp;
  for (size_t i=0; i<q.size(); ++i) for (int v : g[q[i]]) if (seen[v] != stamp) seen[v] = stamp, q.push_back(v);
  return static_cast<int>(q.size());
}
```
